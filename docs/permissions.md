# 권한 표 (PrivacyGate)

| 역할 | 시험 계정 | 할 수 있는 일 | 자동으로 주지 않는 권한 |
|---|---|---|---|
| counselor | `counselor_a` (내부 공격자 A), `counselor_b` | 담당 회원 조회·정보 수정·탈퇴 처리, 담당 회원 증빙 열람·심사, 반출 파일 업로드·신청(본인이 만든 내보내기 결과 등록 포함), 본인 신청 조회 | 전체 회원 내보내기, 증빙 제출·열람, 승인 |
| data_admin (총관리자) | `data_admin` | 보안 사건 확인·조치(잠금 해제·계정 정지·복구·받은 자료 회수), 직원 가입 신청 승인·거절, 전체 회원 조회·정보 수정·탈퇴 처리, 전체 증빙 열람·심사, 전체 회원 내보내기·내역, 배정된 증빙 목록·열람·심사 | **반출 승인** |
| approver | `approver` | 반출 신청 검토·승인·거절·회수 | **전체 내보내기, 원본 증빙 열람** |
| member | `member_b` (외부 공범 B) | 본인 증빙 제출·심사 상태 확인, 매칭, 본인 동의 등록·철회, 본인 탈퇴 신청·철회, 나에게 온 전달 목록·다운로드 (외부 화면만) | 내부 화면 로그인, 증빙 원본 열람, 다른 회원 명의 동의 |
| (Keycloak 운영) | `infra_admin` | Keycloak 관리 콘솔 | 업무 데이터 접근 |

규칙
- 코드 규칙: 직원 `A-C01`(앞글자 A~Z + 역할 C=상담/D=총관리자/P=승인 + 2자리), 회원 `A-001`(A~Z + 3자리, 자동 발급). 코드는 관리자 화면·감사 로그 전용이며 회원 화면에는 나오지 않는다.
- 신원·역할은 서버 인증 정보(세션, Keycloak 서명 토큰)와 `matchmaking_business.users` 에서 확인한다. 요청 본문의 user_id 는 믿지 않는다.
- internal-api 는 역할을 매 요청 DB 에서 다시 읽는다 (비활성화·역할 변경 즉시 반영).
- transfer-api 는 업무 DB 가 없으므로 Keycloak 서명 토큰의 realm 역할로 확인한다. Keycloak 역할과 `users.role` 은 같게 관리한다.
- 신청자 = 승인자이면 서버가 거부한다 (`privacygate.policy.can_decide_request`).
- `GATE_MODE=baseline`(시연 비교용)에서는 관리자 내보내기의 역할 검사와 다운로드의 "요청 file_id ↔ 승인 파일" 연결 검사만 꺼진다. 기본값은 `enforce`.
- 회원은 소개된 상대(`introductions`)에게만 동의를 등록할 수 있다.
- 탈퇴: 담당 직원(총관리자는 전체)이 요청(사유 선택) → 7일 유예 후 자동 삭제. 유예 중인 회원은 매칭·자료 제공이 막힌다.
  - 즉시 탈퇴(바로 삭제)는 총관리자만. 상담 직원이 요청한 탈퇴는 상담 직원·총관리자 모두 철회 가능, 총관리자가 요청한 탈퇴는 총관리자만 철회 가능.
  - 회원 본인도 외부 화면에서 탈퇴 신청(7일 유예)·철회 가능. 직원이 처리한 탈퇴는 회원이 철회할 수 없다.
  - 탈퇴 확정(삭제) 시 그 회원의 Keycloak 세션을 바로 끊고, 안내 기간(`MEMBER_NOTICE_DAYS`, 기본 30일) 동안 로그인하면 "탈퇴된 계정"(직원 처리면 사유 포함) 안내만 보인다. 기간이 지나면 Keycloak 계정도 삭제.
  - Keycloak 계정 삭제는 전용 client `internal-admin`(view-users·manage-users)으로만 하며, 삭제 전에 realm 역할이 member 뿐인지 확인한다 (직원 계정 삭제 불가).
- 회원 간 매칭: 학력 증빙이 통과된 회원만 매칭을 누를 수 있다. 소개된 두 회원이 서로 매칭을 누르면 양쪽 프로필 제공 동의(30일)가 만들어진다. 매칭 취소·탈퇴 시 철회.
- 직원 가입 신청: 로그인 전 누구나 신청할 수 있지만(Origin·횟수 제한), 신청 역할은 상담·승인만이고 승인 전 Keycloak 계정은 비활성·역할 없음이다. 승인·거절은 총관리자(data_admin)만 하며, DB 등록은 `approve_staff_signup` 함수가 승인자가 활성 총관리자인지 다시 확인한 뒤에만 한다. 승인 담당자 승인은 기존 승인 담당자에게도 알림이 간다.
- 회원 알림: 회원은 본인 알림만 조회·읽음·삭제한다(회원 토큰 sub 기준). 알림을 만드는 사건 경로는 transfer-api 서비스 토큰만 부를 수 있고, 사건 종류(kind) 목록 밖의 값이나 문구는 받지 않는다. 증빙 심사 결과 알림은 internal-api가 직접 만든다.
- 회원가입: 외부 가입 폼에서 누구나 요청할 수 있다(로그인 전, Origin·횟수 제한). 만들어지는 계정은 항상 member 역할(Keycloak `members` 그룹)·활성 상태이며, 업무 DB 는 SECURITY DEFINER 함수 `register_member` 로만 저장한다(앱 계정에 users·members INSERT 권한 없음). 비밀번호는 Keycloak 에만 저장한다.
- 새 회원은 활성 상담 직원 중 담당 회원(탈퇴 대기 제외)이 가장 적은 사람에게 배정된다 (같으면 무작위, DB 트리거). 상담 직원은 배정된 회원만, 총관리자는 전체 회원을 본다 (이름·연락처는 둘 다 화면에 없음).
- 직원 승인과 회원 동의는 각각 확인한다. 반출 금지 자료는 승인으로도 허용되지 않는다.
- 권한 선언이 없는 `/api` 경로가 있으면 서버가 시작하지 않는다 (`assert_all_routes_guarded`).
- 서버 간 호출(`/api/internal/*`)은 Keycloak 서비스 토큰의 `azp` 로 호출자를 확인한다.
  - internal-api `/api/internal/disclosure-checks` ← `transfer-api`
  - internal-api `/api/evidence-files` ← `transfer-api` (+ 회원 access token, 회원 증빙 제출)
  - internal-api `/api/internal/member-signups` ← `transfer-api` (회원 토큰 없음, 회원가입) / transfer-api 같은 경로 ← `external-api`
  - transfer-api `/api/internal/*` ← `external-api` (+ 회원 access token)
  - Keycloak 관리 API ← internal-api 의 `internal-admin` client (탈퇴 회원 세션 종료·계정 삭제, 보안 사건 대응 계정 정지·복구)
  - internal-api `/api/internal/security-events` ← `transfer-api` (+ 회원 access token, 공격 ② 알림)

- 사후 대응: 같은 계정이 60초 안에 3번 거부(직원 역할 밖 요청 / 회원 승인 외 자료 요청)되면 15분 자동 임시 잠금. 보안 사건 조회·조치는 총관리자만. 계정 정지·복구는 `set_account_active` 함수가 활성 총관리자인지 다시 확인하며, 본인·다른 총관리자는 대상이 될 수 없다. Keycloak 비활성·세션 종료는 `internal-admin` client 로 하며 data_admin 역할 계정은 거부한다.

권한 자동 시험 (`matchmaking-internal/tests/test_permissions.py`, internal-api 컨테이너에서 실행)
- 다른 상담 직원 담당 회원 조회·수정·탈퇴·철회 404, 증빙 목록에 안 보임
- 즉시 탈퇴는 총관리자만(403), 총관리자 요청 탈퇴를 상담 직원이 철회 불가(403)
- 알림은 본인 것만 조회·읽음·삭제 (남의 알림 id 를 보내도 0건)
- 승인 담당 회원 조회 403, 상담 직원 전체 내보내기 403, 총관리자 소개 자료 요청 403
- 회원 기능은 서비스 토큰 없으면 401, 직원 처리 탈퇴는 회원이 철회 불가, 유예 중 매칭 403
- Keycloak 정리: member 계정만 삭제, 직원 역할이 있으면 거부

인증
- 직원·회원 모두 ID·비밀번호 (OTP 사용 안 함)
- 5회 실패 시 잠금(점증 대기), 비밀번호 12자 이상
- 세션: 유휴 30분, 최대 8시간, 로그인마다 새 세션 ID, 로그아웃 시 서버 세션·Keycloak 세션 종료
- 브라우저 구간은 HTTPS 만 (internal-web·external-web·Keycloak 8443), 세션 쿠키 Secure·HttpOnly·SameSite=Strict

증빙 자동 검사·확장 증빙 (11월 3주)
- 증빙 종류: 학력·재직·신분증·혼인관계·소득·부동산(PDF), 프로필 사진(JPEG·PNG). 원본은 어떤 경우에도 다른 회원에게 제공하지 않는다.
- doc-inspector(로컬 OCR·규칙 탐지·마스킹)는 internal-api 하고만 연결된 inspect-net 에 격리: 인터넷·DB·키·저장소 없음, 읽기 전용, 권한 전부 제거.
- 자동 검사 추출 값(성명·생년월일·발급번호·금액)은 암호화 저장소에만 두고 담당 직원 심사 화면에서만 보인다. 원본 삭제 때 함께 삭제.
- 공개 사실은 직원이 허용 값(구간·여부) 중에서 확정한다. 금액·주소 원값은 저장된 요약에도 들어가지 않는다.
- 신분증은 본인 확인용: 사본을 만들지 않으며 공개 범위가 없다. 연락처 전달 조건(신분증 통과)에만 쓰인다.
- 화면 열람(동의만): 공개 소개·학력·재직·소득 구간·혼인관계·부동산 텍스트. 승인 자료(동의 + 담당 직원 요청 + 승인자 승인): 검토 사진·마스킹 문서 사본·연락처.
- 만남 일정: 두 회원이 직접 제안(최대 3개)·합의한다. 담당 상담 직원은 두 회원이 합의한 후보만 승인(확정)하거나 반려할 수 있고, 직원이 일정을 제안하는 경로는 없다. 승인·반려·조회 때마다 내부 담당 확인 API로 현재 담당 관계를 다시 확인한다.
- 공개 항목 전체(이름·소개·검토 결과·사진·마스킹 문서 사본·연락처): 회원 동의만으로는 상대에게 보이지 않는다. 담당 상담 직원이 동의 범위 안에서 항목을 골라 요청하고 승인 담당자가 승인한 자료만 상대 화면("상대가 허용한 정보")에 표시된다. 이름은 본인 확인 통과 시 '소개 상대' 대신 실명, 연락처는 추가로 두 회원 모두 연락처 동의 + 만남 일정 확정이 있어야 요청할 수 있다. 요청·승인·열람 때마다 다시 확인하며, 동의를 철회하면 즉시 사라진다.
- 마스킹 사본·사진은 저장된 해시와 다르면 자료에 넣지 않는다 (사본 바꿔치기 차단). 중계는 첨부의 형식·해시·파일 머리를 다시 검사한다.
- 내 계정(회원): 비밀번호는 Keycloak 화면(kc_action=UPDATE_PASSWORD)에서만 변경, 앱 서버는 비밀번호를 받지 않는다. 키·몸무게·연락처는 회원 본인만 변경(CSRF 필요), 연락처는 가린 값으로만 표시, 변경 값은 알림·감사 로그에 남기지 않는다. 프로필 사진 등록은 내 계정에서만(증빙 관리와 분리), 직원 검토 후 승인된 사진만 제공 대상.
- 연락처를 바꾸면 이전에 승인된 연락처 자료는 다운로드 시 재검사에서 내용이 달라져 차단된다.
- 매칭 자격(후보 표시·신청·화면 열람·일정·반출 검사): 필수 증빙인 신분증(본인 확인)과 학력이 모두 통과한 회원만. 시험 준비용으로 `infra/scripts/mark-required-evidence.sh` 가 이 두 기록을 만든다(시험 전용).
